# Feature Specification: AngelCal 프로젝트 상위 스펙

**Feature Branch**: `001-angelcal-spec`  
**Created**: 2025-11-27  
**Status**: Draft  
**Input**: User description: "AngelCal iOS 캘린더 앱 전체 프로젝트에 대한 최상위 제품 스펙 요약"

## 제품 비전과 목적
- iOS 18 이상에서 동작하는 개인 중심 캘린더 앱으로, 사용자가 매일 기본으로 여는 주력 일정 관리 도구가 되는 것을 목표로 한다.
- 탁상 달력처럼 한눈에 보이는 월간 뷰와 집중형 주간/일자 뷰를 통해 오늘과 이번 주의 맥락을 최소 탭으로 파악하게 한다.
- 오프라인 우선 전략과 자체 데이터 모델을 통해 외부 캘린더 의존 없이도 안정적이고 예측 가능한 경험을 제공한다.

## 타깃 사용자와 페르소나
- 직관적 월간 뷰와 색상 구분이 필요한 개인 일정 사용자 (프리랜서, 학생, 지식 노동자).
- 개인/업무 캘린더를 함께 보되 복잡한 공유 권한 없이 깔끔한 단일 사용자 경험을 원하는 사람.
- 오프라인에서도 일정 확인·수정이 필요하고, 위젯과 검색으로 빠르게 접근하려는 iOS 사용자.

## 해결하려는 문제와 핵심 가치
- 문제: 기본 캘린더의 월간 가독성 부족, 오프라인 불안, 앱 진입 없이 일정 파악의 어려움.
- 핵심 가치: 한눈에 보이는 구조화된 달력, 오프라인 우선 안정성, 빠른 검색·위젯 접근, 과도한 설정과 공유 복잡성 제거.

## 도메인 개념 요약 (제품 관점)
- **User**: 개인 계정, 언어/지역 설정, 기본 선호 정보를 가진다.
- **Calendar**: 사용자 소유 일정 그룹, 색상/이름/표시 여부/기본 여부를 가진다.
- **Event**: 일정 단위. 시작·종료, 올데이, 위치/메모/링크, 반복 규칙, 알림, 색상 오버라이드 포함.
- **EventTemplate**: 빠른 생성용 기본값 묶음 (제목, 기간, 알림 오프셋, 위치/색상/메모).
- **NotificationSetting**: 기본 알림 시점, 올데이 알림, 데일리 요약, 배지 타입, 사운드 선호.
- **AppearanceSetting**: 주 시작 요일, 공휴일 강조, 테마/폰트/텍스트 크기, 주 번호, 12/24시간제, 언어 오버라이드 등.
- **WidgetConfig**: 위젯 유형, 표시 캘린더 목록, 최대 이벤트 수, 올데이 포함 여부 등.

## 주요 기능 및 화면 범위 (MVP)
- 온보딩/로그인: 스플래시, 핵심 가치 소개, Apple 계정 및 Supabase 연동, 기본 캘린더/설정 초기화.
- 메인 캘린더: 월간↔주간 토글, 날짜 이동·선택, 하단 일자 리스트, 캘린더 필터, 빠른 생성.
- 일정 상세/편집: 상세 시트에서 보기·편집·복사·삭제, 반복 설정, 색상/알림 적용.
- 리스트 뷰: 특정 일자·기간 이벤트를 리스트로 집계, 올데이/시간형 구분.
- 템플릿: 생성/수정/삭제/정렬, 템플릿으로부터 일정 생성 및 반대 흐름.
- 검색/필터: 키워드 검색(제목/메모/위치/링크), 기간·캘린더 필터, 정렬.
- 설정: 캘린더 관리, 외관/테마, 알림/배지, 계정·데이터, 위젯 가이드.
- 위젯·알림: 홈/잠금/스탠드바이 위젯(오늘/다가오는/월간/2-3주), 이벤트 알림, 데일리 요약, 배지.

## 상위 사용자 여정과 핵심 플로우
- 앱 실행: 스플래시→온보딩 여부 확인→로그인/게스트/메인 분기→초기 동기화→메인 탭 진입.
- 메인 탭: 탭1 캘린더(월/주/리스트), 탭2 검색(필터 후 상세 이동), 탭3 설정(캘린더·테마·알림·계정·위젯).
- 이벤트 생성/편집: 캘린더 화면의 탭/롱탭/플로팅 버튼→편집 폼→저장 시 즉시 UI 반영, 알림/동기화 준비.
- 위젯·알림 진입: 알림 탭 시 해당 이벤트 상세로 딥링크, 위젯 탭 시 날짜/이벤트로 딥링크.

## 오프라인 및 동기화 요구사항 (제품 관점)
- 네트워크 없이도 지난 일정·다가오는 일정 확인, 새 이벤트 생성/편집/삭제 가능해야 한다.
- 모든 CRUD는 로컬에 즉시 반영하고, 연결 복구 시 자동 동기화된다.
- 동기화 실패는 최소한의 상태 표시/재시도 옵션만 노출하며 기본 사용 흐름을 차단하지 않는다.
- 다중 기기 사용 시 최신 저장 시각 기준으로 충돌을 단순 해결한다.

## 스코프와 Non-goals
- 스코프(MVP): 개인용 다중 캘린더, 월/주/리스트 뷰, 이벤트 CRUD+복사, 템플릿, 검색+필터, 알림/데일리 요약/배지, 외관 커스터마이즈, 기본 홈·잠금 위젯.
- Non-goals 및 이유:
  - 복잡한 조직 공유/권한: 초기에는 1인 경험 완성에 집중.
  - 외부 캘린더 완전 양방향 동기화: 자체 데이터 모델 완성 후 검토.
  - 유료 플랜/프로 기능 세부 정책: 핵심 경험 검증 이후 결정.
  - 웹/안드로이드 클라이언트: iOS 집중으로 품질 확보.
  - 자동화/고급 분석: 기본 일정 관리 만족도 확보 후 확장.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 오늘/이번 주 한눈 파악 (Priority: P1)
사용자는 아침에 앱을 열어 월간/주간 뷰에서 오늘과 이번 주 일정 밀도를 즉시 파악하고, 하단 리스트로 오늘 일정 세부를 본다.

**Why this priority**: 앱의 주력 가치(한눈에 보는 달력)를 검증하는 핵심 진입 흐름이기 때문.

**Independent Test**: 새 계정으로 온보딩 후 기본 캘린더만 있어도 오늘/이번 주 확인이 3탭 이내로 가능한지 측정한다.

**Acceptance Scenarios**:
1. **Given** 초기 동기화 완료 후, **When** 월간 뷰에서 오늘 날짜를 탭, **Then** 하단 리스트에 오늘 일정이 시간 순으로 표시된다.
2. **Given** 월간 뷰, **When** 주간 토글을 스와이프, **Then** 주간 뷰로 전환되며 선택된 날짜가 유지된다.

---

### User Story 2 - 빠른 일정 생성 (Priority: P1)
사용자는 메인 캘린더에서 빠르게 새 이벤트를 추가하고 즉시 반영되는 것을 본다.

**Why this priority**: 일정 추가 실패나 지연은 핵심 신뢰도를 떨어뜨리므로 MVP 필수.

**Independent Test**: 오프라인 상태에서도 일정 생성 후 리스트와 캘린더에 즉시 나타나는지 확인한다.

**Acceptance Scenarios**:
1. **Given** 월간 뷰, **When** 특정 날짜를 길게 눌러 제목을 입력하고 저장, **Then** 해당 날짜 셀과 리스트에 새 이벤트가 즉시 표시된다.
2. **Given** 기기가 오프라인, **When** 이벤트를 생성 후 재접속, **Then** 동일 이벤트가 유지되고 서버 동기화 후에도 중복 없이 존재한다.

---

### User Story 3 - 일정 수정/이동 (Priority: P2)
사용자는 기존 이벤트 시간을 변경하거나 복사해 다른 날로 옮긴다.

**Why this priority**: 반복적인 일정 관리에서 가장 빈도가 높아 사용 경험에 직접적 영향.

**Independent Test**: 이벤트 상세 시트만으로 시간 변경과 날짜 복사가 완료되는지, 충돌 없이 반영되는지 확인한다.

**Acceptance Scenarios**:
1. **Given** 이벤트 상세 시트, **When** 시간을 변경 후 저장, **Then** 달력과 리스트에서 즉시 업데이트되고 알림 시각도 새 시간 기준으로 재계산된다.
2. **Given** 이벤트 상세 시트, **When** "다른 날짜에 복사"를 선택해 새 날짜를 지정, **Then** 원본 유지 + 새 이벤트가 새 날짜에 생성된다.

---

### User Story 4 - 검색과 필터로 과거 일정 탐색 (Priority: P3)
사용자는 키워드와 기간 필터로 특정 과거 이벤트를 찾는다.

**Why this priority**: 빈도는 낮지만 과거 데이터 회수는 재방문 동기와 신뢰에 기여.

**Independent Test**: 제목/메모/위치 중 하나만으로 검색해도 2초 내 결과가 나오고, 필터 적용/해제 후 리스트가 즉시 갱신되는지 확인한다.

**Acceptance Scenarios**:
1. **Given** 검색 탭, **When** 키워드와 기간 필터를 입력 후 검색, **Then** 일치 이벤트가 최신순으로 표시된다.
2. **Given** 검색 결과, **When** 특정 캘린더 필터를 켜고 끄기, **Then** 리스트가 해당 캘린더 이벤트만/전체로 즉시 전환된다.

### Edge Cases
- 오프라인 상태에서 생성/수정한 이벤트가 여러 건 대기 중일 때, 재연결 시 중복 없이 순차 반영되는가.
- 일자跨월/타임존 변경(DST 포함) 시 월간/주간/리스트 뷰의 날짜 정렬과 알림 시각이 일관되는가.
- 올데이와 시간 기반 이벤트가 같은 날에 많을 때 가독성과 정렬이 유지되는가.
- 템플릿 기본값이 비어 있을 때도 이벤트 생성이 차단되지 않고 합리적 기본값이 채워지는가.
- 검색 결과가 0건일 때 사용자에게 명확한 안내와 필터 초기화 옵션을 제공하는가.
- 동기화 실패가 반복될 때 사용자 흐름을 막지 않으면서 재시도/상태 표시를 제공하는가.

## Requirements *(mandatory)*

### Functional Requirements
- **FR-001**: 사용자는 온보딩을 3분 이내에 완료하고 메인 캘린더에 진입할 수 있어야 한다.
- **FR-002**: 월간 뷰에서 오늘 날짜는 항상 하이라이트되고, 탭 시 하단 리스트가 오늘 일정으로 스크롤된다.
- **FR-003**: 사용자는 월간↔주간 뷰를 제스처 또는 토글로 전환할 수 있으며 선택한 날짜 컨텍스트가 유지되어야 한다.
- **FR-004**: 사용자는 한 날짜에서 3탭 이하로 새 이벤트를 생성하고 저장 후 즉시 달력/리스트에 반영된 것을 확인할 수 있어야 한다(온라인/오프라인 동일).
- **FR-005**: 오프라인에서 생성·편집·삭제한 이벤트는 연결 복구 시 자동 동기화되어 중복 없이 단일 이벤트로 남아야 한다.
- **FR-006**: 검색 화면은 제목·메모·위치·링크를 대상으로 키워드 검색을 제공하고, 기간 및 캘린더 필터를 조합 적용할 수 있어야 한다.
- **FR-007**: 이벤트 상세 시트에서 시간 변경, 복사, 삭제, 알림/색상 수정이 가능하며 저장 시 즉시 UI에 반영되어야 한다.
- **FR-008**: 템플릿 생성/수정/삭제가 가능하고, 템플릿에서 이벤트를 생성할 때 기본값이 자동 적용되어야 한다.
- **FR-009**: 사용자 설정에서 캘린더 색상, 기본 캘린더, 주 시작 요일, 테마, 텍스트 크기, 12/24시간제, 휴일 강조를 변경하면 메인 뷰와 위젯에 즉시 반영되어야 한다.
- **FR-010**: 알림 설정에서 기본 알림 시점, 올데이 알림, 데일리 요약, 배지 타입을 제어할 수 있어야 하며, 변경 시 이후 이벤트/요약 알림에 적용된다.
- **FR-011**: 위젯 구성은 위젯 타입과 표시 캘린더, 이벤트 개수, 올데이 포함 여부를 선택할 수 있어야 하며, 저장 후 다음 새로고침 시 반영된다.
- **FR-012**: 초기 동기화는 계정의 캘린더/이벤트/설정을 로컬에 내려 받아 메인 화면 진입 전 최소 사용 가능한 상태를 보장해야 한다.
- **FR-013**: 다중 기기 사용 시 동일 이벤트에 대한 최신 저장 시각 기준으로 데이터가 일관되게 표시되어야 한다.
- **FR-014**: 오류 발생 시 사용자 친화적 메시지와 재시도/취소 선택지를 제공하며, 일정 데이터 손실 없이 이전 상태로 복귀할 수 있어야 한다.

### Key Entities
- **User**: 개인 계정, 언어/지역/알림 선호를 가진다; 여러 캘린더를 소유.
- **Calendar**: 이름, 색상, 기본 여부, 표시 여부; 한 User에 다수 존재.
- **Event**: 제목, 시작/종료, 올데이, 반복, 위치/메모/링크, 색상 오버라이드, 알림; 한 Calendar에 속함.
- **EventTemplate**: 기본 제목/기간/알림 오프셋/위치/색상/메모; 이벤트 생성 시 기본값을 제공.
- **NotificationSetting**: 기본 알림 타이밍, 올데이 알림 여부, 데일리 요약, 배지 타입, 사운드 선호.
- **AppearanceSetting**: 주 시작 요일, 테마, 폰트/텍스트 크기, 주 번호, 12/24시간제, 공휴일/음력 표시 등.
- **WidgetConfig**: 위젯 타입, 연결 캘린더, 최대 표시 이벤트 수, 올데이 포함 여부.

## Success Criteria *(mandatory)*

### Measurable Outcomes
- **SC-001**: 신규 사용자의 80%가 첫 실행 후 3분 내 온보딩을 완료하고 메인 캘린더 진입.
- **SC-002**: 오늘/이번 주 확인까지 평균 탭 수 3 이하, 평균 소요 시간 15초 이하 (사용 로그 기준).
- **SC-003**: 오프라인 상태에서 생성·수정한 이벤트의 동기화 성공률 98% 이상, 중복/유실 발생률 0.5% 미만 (릴리즈 모니터링 기준).
- **SC-004**: 키워드+필터 검색 결과가 2초 이내 표시되는 비율 95% 이상 (측정 환경: 최근 90일 데이터 사용자 샘플).
- **SC-005**: 월간/주간 뷰 스크롤·전환 시 60fps 체감 유지에 대한 사용자 만족도 설문 80% 이상 긍정.
- **SC-006**: 알림/위젯을 통한 진입 후 목표 이벤트 상세 도달 성공률 95% 이상.

## 가정과 오픈 이슈
- 가정
  - 주 사용 환경은 단일 iOS 디바이스이나, 다중 기기 동기화를 단순 정책(최신 저장 우선)으로 지원한다.
  - 초기 론칭은 한국어/한국 로케일을 우선하며, 추가 언어는 후속 릴리즈에서 확장한다.
  - 개인용 사용을 전제하고 공유/조직 기능은 단순 뷰 수준으로만 고려한다.
- 오픈 이슈
  - 유료 플랜 시점과 포함 기능 결정 필요.
  - 공휴일·음력 데이터 소스 및 갱신 주기 확정 필요.
  - 검색 인덱싱 범위(예: Spotlight 연동)와 성능 목표 조정.
  - MVP에 포함할 위젯 타입 우선순위 최종 확정.
